# providers · 图像生成 Provider

**目录**:`backend/app/providers/`
**图**:[Provider 错误策略](../assets/provider-error-policy.svg)

## 边界

这一层只回答三件事:这一家**能不能用**、**怎么把请求发出去**、**失败了算哪一类**。
它不知道轮次、不知道分档、不碰数据库。

```
capabilities()   支持哪些生成模式、一次最多出几张
is_configured()  缺 Key / 缺地址时 False —— 只读配置,绝不发网络请求
submit()         提交生成,返回外部任务 ID
get_status()     查外部任务状态
fetch_results()  取回候选图(URL 或字节)
```

`is_configured()` 处在应用启动路径和 `GET /api/providers` 上,这两条路径必须极其
健壮 —— 任何一个可选依赖缺失都不该让 Provider 页面打不开。所以它只允许读配置。

## 四个已注册的实现

| 名字 | 状态 | 说明 |
| --- | --- | --- |
| `mock` | 可用 | 用 Pillow 真出图;可模拟成功 / 失败 / 超时 / 空结果 / 限流 / 内容安全 |
| `fashn` | 已实现,未用真实 Key 验证 | 请求 / 状态 / 错误映射、轮询、自检齐备,见 [`../PROVIDER-FASHN.md`](../PROVIDER-FASHN.md) |
| `fal` | 骨架 | 请求映射待官方文档确认 |
| `comfyui` | 骨架 | 同上,节点 ID 必须来自配置,见 [`../../comfyui/README.md`](../../comfyui/README.md) |

`IMPLEMENTED_PROVIDERS` 与 `is_configured()` 共同决定 `selectable_names()` ——
也就是「现在真的能选」的那几家。方案表单读它,**不是**硬编码一份名单:
硬编码的后果是运营能一路走完「选 comfyui → 存草稿 → 启用」,三天后创建任务才拿到
报错,而那时错误指向的是任务,不是方案。

## 三条不能破的约定

**未配置的 Provider 不得被选中。** 任务在创建阶段就被挡下,而不是跑到一半才失败。

**切换只能由明确规则触发。** 路由是纯函数:`MANUAL` 用任务里指定的那家,
`PRIORITY` 按固定顺序挑第一个已配置且支持该模式的。不存在「模型自由决定用哪家」。

**`is_simulator` 默认 True(先假设是假的)。** 两个方向的错误代价不对称:
忘了在一个新的真 Provider 上写 `False` → 状态条多喊一次「这是模拟环境」,人一眼看得见,
当场就会来改;忘了在一个新的 Mock 上写 `True` → 状态条安静地说「真的在调外部出图服务,
会产生费用」,而运营会照着一批假图批准上架。

## 错误策略

两个布尔决定一切:`retriable`(同一家再试有没有意义)、`switchable`(换一家有没有
意义)。未知错误码按**最保守**的基类策略处理。三处容易看反的:

- **限流 vs 配额用尽。** 限流等一会儿就好,配额用尽等多久都不会好 —— 必须有人去充值。
- **结果下载失败 `switchable=False`。** 地址已经拿到了,说明上游那次生成**已经成功
  且已计费**;换一家等于重新付一次钱去解决一个网络问题。
- **超时不代表对方没收到。** 恢复流程必须先查外部任务状态再决定是否重提,
  否则会重复计费并产生孤儿任务。

## 出网安全

结果图要从第三方地址下载,所以每一跳都过 `core/net_safety`。适配器可以用
`trusted_result_hosts` 声明自己**精确的**结果域名(某些代理的 fake-IP 模式会把公网
域名解析到 `198.18.0.0/15`,那个网段必须继续被通用 SSRF 防线视为内网)——
只在主机名精确相等时追加,相似后缀、子域名和重定向目的地都不继承信任。
