这不是巧合,是一个信号:**这条线上判定的密度已经很高,而守卫的质量没有人
系统查过。**判定有变异验证兜底(每批 20~34 条),守卫本身只有「它今天跑绿」
这一条证据 —— 而假绿守卫的定义就是「它跑绿」。

## 二、失效方式只有一种形状,而它不响

    窗口是按字符串定位切出来的,而定位串在文件里不止一处
    窗口是定长的(`[:200]`、`[i : i + 400]`)

被切窄之后:

    正向断言   碰巧还在残段里 -> 一切看起来正常
    反向断言   被残段喂成**平凡真** -> 守卫悄悄不设防,并且照样打印 PASS

14-13 撞见的两条:一条的定位串 `),` 被登记项注释里的 `(归属外键不存在),`
提前命中;另一条用的是定长窗口 `[:200]`,而那一批往登记项里加了一行之后,
它的反向断言(「`idempotency_key` 不许被登记」)**再也拦不住任何东西**。

## 三、判据为什么只管反向断言

全树扫下来,按字符串定位切窗口的地方有 **87 处**。一刀切「不许这么写」
会把绝大多数正当用法一起判红,而**它们的失效是响的**:

| | 窗口切窄之后 | 谁会发现 |
|---|---|---|
| 正向断言 | 断言变假 → 红 | 有人会看见 |
| 反向断言 | 断言变真 → 绿 | **没有人会看见** |

规矩要挑那条不响的。缩到「喂给反向断言的窗口」之后,全树只剩 **10 处**,
零容忍是做得到的 —— 而一条有出路的门禁才不会被加白名单。

## 四、收口的办法:三个工具,对应三种「这一段到哪为止」

    window(text, start, end)   两端都是**地标**(各自唯一)
    braced_block(text, start)  终点是**分隔符**,按括号配平
    only_line(text, prefix)    范围就是一行,行首锚定

`window()` 保证三件事:起点恰好出现一次、终点在起点之后恰好一次、
起点之后确有内容。「恰好一次」这条口径和 `tools/audit_anchors.py`
对变异锚点的要求同源 —— **一个不唯一的锚点,和一个没有锚点是一回事。**

后两个是被逼出来的,不是设计出来的:

- **`braced_block`**:nginx 那条守卫原来按「第一个 `}`」切。今天恰好对,
  因为那个 location 没有嵌套 —— 而那不是一条能靠的性质:里面出现一个 `if`
  就多一层括号,切窄之后反向断言静默变真。用 `window()` 会被当场挡回来
  (`}` 在起点之后出现很多次),**而挡回来是对的**:花括号块的终点是分隔符,
  本来就不该拿地标去框。
- **`only_line`**:写本批那条注册守卫时,`check-offline:` 与
  `check-offline: test-pure` **都被 `window()` 挡了回来** —— 两次都因为
  Makefile 里有一句引用旧写法的注释。行首锚定天生挡得住 `#` 开头的注释,
  而子串计数挡不住。连撞两次才想明白**行**这种范围该有自己的工具。
