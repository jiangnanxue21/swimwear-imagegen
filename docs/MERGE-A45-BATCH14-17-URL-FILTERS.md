## 二、为什么不能给 `useUrlSeed` 打补丁

上一版自己把代价写清楚了:「参数擦掉之后地址栏不再带筛选条件,
**刷新页面会回到全量列表**」。于是 §8.2 的四条要求里只剩「点进来能带条件」
一条成立。

而这修不成一个补丁,因为病根不是 `clear()` 这一行:

    只要 URL 是初值,组件内那份 state 就是第二处真相
    两处真相之间任何一次重新同步都要在「谁顶掉谁」上做选择
    擦参数,正是当时为了不让 URL 顶掉运营的手选而做的取舍

所以口径翻过来:**URL 是唯一真相**,组件内不存筛选值,`clear()` 连同整个
hook 一起删掉。删而不是留:**能被抄的旧做法就是活的** ——
下一个加筛选页的人照着它抄,抄回来的东西刷新就丢,而且不会有任何东西报错。

## 三、搬了四页,而原文只点名三页

`STATUS` 那一行点名的是工作台列表 / 生成任务 / 逐件快审。**操作审计页
一起搬了**:它用的是同一个 hook、同一个缺陷 —— 顶栏「我的操作记录」
那个链接刷新一次就变回全站记录,界面承诺了「我的」,给的是「所有人的」。

只搬三页的话,`useUrlSeed` 就删不掉,而删不掉就等于这条 gap 没关。

| 页 | 搬进 URL 的项 |
|---|---|
| 工作台列表 | 搜索、步骤、状态、下一步动作、受众、只看阻断、页码、每页条数、排序两项 |
| 生成任务 | 状态、页码、排序两项 |
| 逐件快审 | 分段器(游标**刻意不进**,见下) |
| 操作审计 | 操作人、对象类型、业务动作、时间范围、只看上架闭环、页码、每页条数 |

**参数名一个都没改**,所以首页卡片、顶栏链接、旧书签照旧能用;
区别只是落地页不再把它们擦掉。

## 四、BLOCK-09 会从一扇新门原样回来

这是本批最要紧的一条,写在 `useUrlFilters` 的 `signature` 注释里:

    URL 化之前,「换筛选就清空勾选」靠六个入口都走 changeFilter() 一个口子
    URL 化之后**后退、前进、直接编辑地址栏都会改筛选,而它们一行 JS 都不经过**

勾 20 件 → 按一次后退 → 动作条仍说「已选 20 件」→ 点批量识别,
提交的是那 20 件,其中大部分不在他眼前。**「执行前显示可执行数量」
那个确认框救不了它:数字本身是对的。**

清空改挂在 `filters.signature` 上 —— 不管筛选是被谁改的,它都变。
快审的游标同理(不复位的表现:后退换回上一类,游标还停在第 7 位,
而新队列只有 3 件)。

`signature` 是**规范形式**而不是 `params.toString()`:`?page=1` 和不带 page
是同一个状态,拿原始查询串当依赖会白白清一次勾选,
而「勾选莫名其妙没了」只要发生过一次,运营下次就不敢用批量了。

## 五、游标不进 URL,勾选也不进

筛选是**条件**(在两个人那里意思一样),游标是**位置**(不是)。
把 `?index=7` 贴给同事,他打开看到的是另一件商品 ——
一个**看起来精确、实际上指错**的地址比不带它更贵。守卫钉着这一条。

## 六、一条变异漏网

第一轮 13 条变异里 **U5 没被抓住**:

    read: (raw) => (raw === '1' ? true : raw === '0' ? false : fallback)
    read: (raw) => raw === '1'

看起来只是"少认一种写法",实际后果是 **`raw === null` 时返回 `false`** ——
审计页在**没有任何参数**的默认状态下,「只看上架闭环」变成关着的。
那个开关默认开着是刻意的降噪,关掉之后运营要在生成任务的状态流转里
找批准和导出记录,而**界面上的开关和数据是一致的**、没有任何地方报错。

补了 `test_every_codec_falls_back_to_its_own_default_when_it_cannot_read_the_value`。
漏的原因写在那条守卫里:上一版只守了 `write`(默认值不进 URL),
而这两半的失效方向不一样 ——

    默认值漏进 URL   看得见(地址变长)
    默认值读错       只是行为变了
