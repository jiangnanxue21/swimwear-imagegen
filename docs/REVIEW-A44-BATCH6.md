## 二、两条只做了一半，说清楚为什么

### C-04：不删回落，只让它可见

没有运营口令时，普通请求会带上**管理口令**。这个回落是 A5 刻意留的——
只配 admin 的部署照样能用，后端本来也认 admin 包含 operator。**删掉它，
那类部署会整站 401，那不是修复。**

但代价是真的：每一次列表 GET 都在发送能改 API Key 的那把口令，而运营
完全看不到这件事正在发生，也就没有任何理由去补一把运营口令。

所以这一批做的是：`useIdentity` 暴露 `usingAdminFallback`，冷启动横幅
据此给出提示。**真正消除它要账号体系（C-05'），不是一个前端改动。**

### C-11：只把峰值从"必然 20MB+"降到"超限时早停"

`asset_service.upload_asset()` 收的是 `bytes`（要算哈希、探尺寸、交给存储层），
所以整份内容终究要在内存里过一遍。真正的流式要把它改成收文件对象，
连同存储层的分段上传一起动——那是另一件事。

这一批做的是两件：**先看 `Content-Length`**（头里就写着超限的，一个字节都
不读就拒；它可以撒谎，所以只是快速路径不是判据）、**分块读超一块就停**
（真正的判据，且立刻 `chunks.clear()`）。

顺带把两个上传入口（素材、模特模板）收敛到 `deps.read_within_limit()` 一份。

## 三、A-22 的做法：猜不出来就不猜

异常分支原来硬编码 `paid_calls=0`。付费调用之后抛出的异常（响应解析失败、
落库失败、重试到放弃）照样花了钱，而少记的那一笔**不会让任何数字对不上**，
所以永远不会有人发现——与同仓"宁可多算不少算"的方向正好相反。

执行器自己知道花没花钱，所以约定由它带出来：`PaidCallFailure(msg, paid_calls=n)`。
读的是**属性**不是类型——包过一层的异常只要把属性透传出来就仍然算数。

没带出来的仍然记 0。那是一个**已知的少算**，写在代码里让下一个人看得见，
而不是让它继续无声。

## 四、C-14 立的是棘轮，不是修复

评审对 C-14 的结论是"属实且防御到位，**缺的是静态规则/契约测试**"。
防御指 `label_of()` / `nameOfVariant()`，而没有任何东西拦住下一个人绕开它们。

所以这三条在改动前的代码上就是**绿的**——它们不是在修 bug，是在钉住一个
今天恰好正确的形状：key 不许直接显示给人看、两端"显示名"口径必须同向、
命名空间形式必须可逆（拼得出拆不回来的话，C-13 那种切错会再来一次）。

## 五、第三次撞见"门禁钉的是写法不是不变量"

这一批改动让**两条既有门禁**当场变红，而被它们保护的不变量一个字都没变：

| 门禁 | 它钉的 | 应该钉的 |
|---|---|---|
| `test_per_image_billing_semantics_are_untouched` | 一整串字面量 `attempted = int(extraction.image_count or 0)` | `attempted` 从 `image_count` 推出来 |
| `test_upload_limits_come_from_settings_at_the_api_layer` | `products.py` 源码里出现 `MAX_UPLOAD_SIZE_MB` 这个词（而它只出现在**错误文案**里） | 调用方从 settings 取上限，执行方按它拒绝 |

加上第五批那条要求租约不变量必须写成 `assert` 的，**这是第三次**。

形状是一样的：门禁钉住了当时的写法，于是任何一次让代码更正确的重构都会
先看到红，而红的时候最省事的做法是把代码改回去。两条都已改成钉 AST/不变量。
