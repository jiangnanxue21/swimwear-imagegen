## 二、这一笔账为什么躲过了四批

面板(`GenerationPlanPanel.tsx`)与客户端(`api/generationPlans.ts`)在
A45-batch14-20 就写完了。之后四批的交接给出过三种理由,而只有最后一种是对的:

```
14-20    「跑不了 tsc / Vitest」            真的,但那是环境限制,不是这一笔
14-23    「等有人写一行 import」            **错的** —— 无处可写
14-23 后 「缺一个知道 SPU 主键的宿主页」    对的
```

第二条是本仓 §3.33 反复点名的那一类:**一条过期的理由比没有理由更糟。**
面板要 `spuId`(UUID),而当时前端没有任何一条路径拿得到 SPU 主键 ——
聚合页只有 `spu` 字符串码,`publish.ts` 的 `external_spu_id` 是**平台侧**外部 id,
唯一在出参里给 `spu_id` 的 schema 是方案接口自己(要拿主键得先有方案,
要列方案得先有主键)。照着"写一行 import"去做的人会发现无处可写,
然后多半随手把字符串码传进 `spuId`,那时接口 422,**而错因指向后端**。

所以缺的不是一行 import,是一个知道 SPU 主键的页面。本批落的就是它。

## 四、两个决定

### D1:主键推不出来时给 `None`,不挑一个

分组键是 `spu` 字符串码,而主键住在每一行商品上,所以 `SpuGroup.spu_id` 做的是
一次**收敛**而不是一次读取。三种情况:

| 情况 | 给什么 |
|---|---|
| 全组同一个非空值 | 给它 |
| 一个非空值都没有(老建档路径) | `None` |
| **两个以上不同值** | `None` |

第三种是这个属性存在的理由。挑一个出来的代价不是"显示错一个 id":
运营点进去看到的是**另一个款**,方案面板会照着那个主键列方案、启用、
把别人的图片集判过期 —— 而每一步都不报错。与 `FieldConsistency.value`
(不一致时返回 None)同一条口径。

**半迁移的一组仍然给主键**(非空的那些一致时)。备选是一律给 `None`,
代价更贵且更隐蔽:迁移逐批做,中间态可能持续很久,而那期间这一页会说
"这个 SPU 配不了方案",没有任何地方解释为什么。守卫
`test_a_half_migrated_group_still_reports_the_key_the_migrated_rows_carry`
钉着这个决定,变异 A2 是它的反方向。

### D2:宿主页是新的一页,不是挂在 SPU 聚合页的展开行里

聚合页按字符串码分组,一行可能对应"没有主键的老商品"。把面板铺在那张表的
展开行下面,等于让一个**只在部分行上成立**的功能长在每一行下面,
而不成立的那些行没有任何视觉差别。

现在的分法是:聚合页回答"哪个 SPU 该处理",详情页回答"对这个 SPU 做什么"。
聚合页只在后端真给了主键时才给出链接,给不出时用 tooltip 说明为什么。

## 六、变异第一轮 13/14,漏的那条是本仓第四次同型

**C2**(把宿主页那行 import 注释掉)第一轮 **GREEN**。两层原因,都值得记:

1. 断言查的是整份源码里有没有 `GenerationPlanPanel` 这几个字,而
   `// import GenerationPlanPanel ...` 照样命中 —— **注释替实现喂真**。
   同一个坑在本仓是第四次(batch13-3 的 M11、batch14-2 的 N15、14-22 的 L5)。
   前三次的修法都是"把断言锚得更死";这次换成**从输入里把注释去掉**
   (`_code_only()`),因为解释性文字本来就不该参与判定 ——
   锚点再准也挡不住下一段刚好提到它的注释。
2. 剥掉注释之后它**仍然绿**:JSX 里的 `<GenerationPlanPanel .../>` 接着把断言喂真。
   而那一刻组件根本不存在(tsc 会红,纯层看不见)。
   「出现了某个名字」不等于「那个名字是从这里来的」—— 断言最终钉在
   **import 语句**上,渲染另有一条。

### 第 5 条要走的那条动线(本批的全部价值都在这一段)

```
三步建档建一个三颜色 SPU
  → 完成页点「去配置生成方案」            期望:落到 /spus/<uuid>,颜色表有三行
  → 面板「存为草稿」,作用域选一个颜色      期望:列表多一行 DRAFT
  → 点「启用」                            期望:先弹窗列出会过期的颜色,再落 ACTIVE
  → 回 SPU 聚合页,点该 SPU 的编码          期望:链接进得去同一页
  → 找一个 CSV 导入建的老商品              期望:**没有链接**,tooltip 说明原因
  → 断网后刷新聚合页                      期望:空态说"拉不到",不说"还没有商品"
```

最后两条是本批新加的行为,没有任何自动化验证够得着它们。

### 还要盯一眼的两处

- `GET /workbench/spus` 的出参多了 `spu_id` 一列。**旧前端不会因此坏**
  (多一个字段而已),但如果有第三方消费者按字段数校验,那里会红。
- 老建档路径的商品在这一页上从此**可见地**少一个能力。这是如实展示,
  不是回退 —— 在此之前它们和新商品长得一样,而点进去会 422。
